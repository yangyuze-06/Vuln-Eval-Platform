## 🔍 问题分析

### 核心发现

1. **Mac 平台漏报 67 个真正例**
   - 6 个 CWE 受影响（022, 078, 079, 089, 501, 643）
   - 5 个 CWE 完全一致（090, 327, 328, 330, 614）
   - Recall 从 100% 下降到 95.26%

2. **数据库层面的不一致**
   - Mac 和 Linux 编译的 CodeFuse 数据库存在差异
   - 相同的源代码、相同的 CodeFuse 版本，但数据库内容不同
   - 这与 `idea/question.txt` 中记录的问题一致

3. **漏报模式**
   - 主要影响污点追踪相关的 CWE（命令注入、路径遍历、SQL 注入、XSS）
   - 密码学相关的 CWE (327, 328, 330, 614) 完全一致
   - 说明数据流分析在不同平台有差异

---

## 🛠️ 根本原因

### 已确认的问题

**CodeFuse 数据库跨平台编译不一致**

- **现象**: 在 Mac 上编译的 `coref_java_src.db` 与 Linux 上编译的数据库内容不同
- **影响**: 同一个查询在不同数据库上返回不同结果
- **证据**: 
  - Mac 数据库: 258MB, SQLite 3.41.2, 创建于 2026-06-12 16:12
  - 查询结果少了 67 个漏洞检测

### 可能的技术原因

1. **编译器差异**
   - macOS 和 Linux 的 Java 字节码可能有细微差异
   - CodeFuse 数据库构建工具对平台敏感

2. **文件系统差异**
   - macOS (APFS) vs Linux (ext4/xfs)
   - 文件路径大小写敏感性不同

3. **数据库构建顺序**
   - 不同平台的文件遍历顺序可能不同
   - 影响数据库索引和查询优化

## 📋 解决方案

### 方案 1: 使用 Linux 编译的数据库（推荐）

**优点**:
- Linux 结果 Recall=100%，完全覆盖所有真正例
- 避免 Mac 平台的数据库构建问题

**操作**:
```bash
# 从 Linux 机器复制数据库
scp linux-machine:~/path/to/coref_java_src.db dataset/codefuse-db/
```
